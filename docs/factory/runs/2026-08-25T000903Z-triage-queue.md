## Charter gaps (for a human)

New this run:

1. **No post-merge exit from `awaiting-review` is defined.** The contract says the
   source issue stays `awaiting-review` "until a human merges or closes the work" but
   never says what happens *after* the merge. This run inferred that #29 returns to the
   queue as `wait-to-implement` (umbrella blocked on its slices). That inference is
   reasonable but it is an inference — the state machine should name the transition.
2. **Umbrella/tracker issues are not covered.** #29 tracks no files and no direct work;
   its "done" is entirely "slices land, human closes". Used wait-to-implement with a
   done_when of exactly that, but the charter is silent on issues whose work is fully
   delegated to other issues.
3. **May triage re-stamp a handoff comment written by another stage?** #33's comment
   came from the spec run. This run updated it in place (refreshed `triaged_at`,
   appended `reconfirmed_by`) on the reading that "update rather than accumulate
   conflicting copies" applies. If `triaged_at` is meant to be immutable provenance of
   the original classification, the contract should say so.

Still open from earlier runs (unanswered, restated so they are not lost): no
disposition for "already fixed at HEAD" (#4 sits in needs-info for this reason); no
routine is authorized to close an issue; single-file-fix vs new-test-file counting;
route for findings whose fix is an existing-test edit; whether in-source comments
count as "docs" for claim fixes; re-verification duty for aged findings.

Also noted, not a charter gap: the factory policy files (`CHARTER.md`, `CONTRACT.md`,
`.claude/`, `.factory/`, `AGENTS.md`, `CLAUDE.md`, …) exist only as untracked local
files — `origin/main` tracks `docs/factory/QUEUE.md` and `runs/` but none of the
policy. If another machine (or a fresh clone) runs a routine, it will read a
repository without its own rules. Whether that is deliberate is an owner call.
