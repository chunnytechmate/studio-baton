# FQ-38 — Vertical slices

All slices are Draft, load-bearing, deep-gated, independently verified, and below 400
changed lines. Dependencies are merge-order gates; a waiting slice is not claimable.

## Slice 0 — enforcement tracer

Synthetic GitHub payloads prove bootstrap/strict rule previews, app-bound check inventory,
auto-merge-off, explicit `--apply`, and denied-capability probes without a live mutation.

## Slice 1 — tracked authority

A clean `origin/main` worktree contains the approved AGENTS/Claude adapter, contract, and
charter; their authority, fork model, readiness, audit, and approval rules agree.

## Slice 2 — green bootstrap baseline

After same-session approval for the existing test, PR-only zero-check protection is active;
only mechanical baseline formatting changes, deep gates pass, and the merged `main` CI is green.

## Slice 3 — local gate parity

Tracked gate/config/doctor files make unformatted code fail the local lint judgment and
formatted code pass while preserving the `FACTORY_GATES` schema; deep is configured.

## Slice 4 — append-only audit primitive

Run/readiness records append to the audit branch with bounded race retry; first-blob
mutation/deletion is detected as `MISCONFIGURED` and never opens an audit PR.

## Slice 5 — readiness and standard feature flow

Implement/spec workflows support canonical progress/resume, Draft-through-CI, exact-SHA
verification, append-before-label readiness, one standard spec packet, and old handoffs.

## Slice 6 — audit routines

Triage, monitor, and tune write full audit-branch records without PRs; their adapters retain
live issue handoffs and stop fail-closed on audit-integrity or credential failure.

## Slice 7 — activation and control room

Fork/coordinator credentials fail all merge/auto-merge/admin probes, exact green contexts
become strict required checks, the control room reports real decisions, and legacy open PRs
are reconciled before `enforcement: active`.
