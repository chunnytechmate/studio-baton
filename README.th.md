# Studio Baton

[English](README.md) · ภาษาไทย

Studio Baton คือเครื่องมือ CLI สำหรับงานหลังบ้านของสตูดิโอสอนดนตรีตัวต่อตัว ครอบคลุมข้อมูลผู้เรียน เอกสารรายคาบ สรุปบทเรียน การส่งข้อความ วิดีโอ และปฏิทิน เอเจนต์หรือสคริปต์จึงเรียกงานที่มีกฎชัดเจนได้โดยไม่ต้องประกอบคำขอ API ใหม่ทุกครั้ง

> **สถานะ: 1.0.2 · Production/Stable** วงจรตั้งแต่จองคาบ จัดการวิดีโอ เขียนสรุป จนถึงส่งรายงาน ทำงานครบในวันสอนจริงแล้ว แพ็กเกจติดตั้งได้จาก PyPI ภายใต้สัญญาอนุญาต MIT

## ที่มาของโปรเจกต์

Studio Baton เติบโตจากงานที่ใช้จริงในห้องเรียน โดยผ่านการพัฒนาสี่ช่วง:

**Class Summarize scripts → PLAM → OpenClaw skills → Studio Baton**

สคริปต์รุ่นแรกพิสูจน์ว่างานวิดีโอและสรุปบทเรียนทำเป็นระบบได้ PLAM นำงานเหล่านั้นมารวมไว้ในผู้ช่วยเสียงภาษาไทย ต่อมาผมย้ายเครื่องมือไปเป็น skills บน OpenClaw เพื่อแยกบริบท จัดคิว และกู้คืนงานได้ดีขึ้น แต่เอเจนต์ยังต้องอ่านคำสั่งยาวและประกอบ API เอง Studio Baton จึงเปลี่ยนขั้นตอนที่มีกฎชัดเจนให้เป็นคำสั่ง รูปแบบข้อมูล และด่านตรวจที่ทดสอบได้

## วงจรหนึ่งคาบ

1. **จองคาบ** ด้วย `baton calendar` ระบบเลือกผู้เรียนและอัปเดตเอกสารก่อนสร้างกิจกรรมในปฏิทิน
2. **สอนและบันทึก** ครูสอนตามปกติ แล้ววางคลิปไว้ใน Google Drive หรือโฟลเดอร์ที่กำหนด
3. **จัดการวิดีโอ** ด้วย `baton video` ระบบรวมคลิป อัปโหลด และผูกลิงก์กลับเข้าคาบ งานที่สะดุดกลางทางกลับมาทำต่อจากจุดเดิมได้
4. **เขียนสรุป** ด้วย `baton lesson` Baton เตรียมบริบทกับ JSON Schema ให้โมเดลภายนอก จากนั้นตรวจข้อมูล แสดงฉบับเต็มให้คนอ่าน และเผยแพร่หลังได้รับการยืนยัน
5. **ตรวจและส่ง** ด้วย `baton send` ระบบตรวจข้อมูลบังคับก่อนส่งและเก็บหลักฐานการส่งไว้

วงจรนี้ไม่ได้ทำทุกอย่างด้วยคำสั่งเดียว แต่ละช่วงแยกจากกันเพื่อให้คนตรวจผล แก้ข้อมูล หรือหยุดงานก่อนแตะข้อมูลจริง

## คำสั่งระดับบน

| คำสั่ง | หน้าที่ |
| --- | --- |
| `baton init` | สร้างโปรไฟล์เริ่มต้น |
| `baton schema` | แสดง SQL อ้างอิงสำหรับ SQLite หรือ PostgreSQL |
| `baton doctor` | ตรวจไฟล์ตั้งค่า ข้อมูลรับรอง และบริการที่ต้องใช้ |
| `baton config` | แสดงค่าที่ระบบอ่านได้จริง |
| `baton learner` | เพิ่มและค้นข้อมูลผู้เรียน คาบ เพลง และผลงาน |
| `baton song` | จัดการแค็ตตาล็อกเพลง |
| `baton course` | วางแผน ตรวจ และล้างคอร์สหลังเก็บสำเนาแล้ว |
| `baton lesson` | เตรียม ตรวจ แสดงตัวอย่าง เผยแพร่ หรือยกเลิกสรุป |
| `baton send` | ตรวจความพร้อม ส่งข้อความ และรายงานสิ่งที่ค้าง |
| `baton video` | รวม อัปโหลด และผูกวิดีโอกลับเข้าคาบ |
| `baton calendar` | จองหรือยกเลิกคาบโดยรักษาเอกสารกับปฏิทินให้ตรงกัน |
| `baton notes` | แปลง Markdown และส่งขึ้นพื้นที่เอกสาร |
| `baton job` | ดูแลคำสั่งที่รันเบื้องหลัง |
| `baton prep` | สร้างรายงานเตรียมสอนประจำวัน |

คำสั่งระดับบนสุด 14 กลุ่มนี้มีเส้นทางคำสั่งสำหรับผู้ใช้รวม 63 แบบในรุ่นปัจจุบัน โดยไม่นับ `baton job supervise` ซึ่งเป็นคำสั่งภายใน

## ติดตั้ง

```bash
pip install studio-baton
pip install "studio-baton[google]"  # เพิ่ม Drive, YouTube และ Calendar
```

รองรับ Python 3.10–3.14 บน Linux และ macOS ส่วน Windows ไม่รองรับ เนื่องจากงานเบื้องหลังอาศัยสัญญาณและการล็อกไฟล์แบบ POSIX

## ขอบเขตของ AI

AI ทำหน้าที่เรียบเรียงสรุปบทเรียนเท่านั้น Baton เตรียมบริบทกับ JSON Schema ให้โมเดลภายนอก แล้วตรวจคำตอบก่อนจัดหน้าและเขียนลงเอกสาร ส่วนการเลือกผู้เรียน คำนวณวัน ตรวจฟิลด์ ประกอบข้อความ และเรียกบริการภายนอกเป็นหน้าที่ของโค้ดที่ทดสอบซ้ำได้

```bash
baton lesson contract "ชื่อผู้เรียน"
baton lesson ingest "ชื่อผู้เรียน" --file summary.json
baton lesson render "ชื่อผู้เรียน"
baton lesson publish "ชื่อผู้เรียน"
```

## ด่านความปลอดภัย

- คำสั่งทั่วไปเลือกผู้เรียนจากชื่อเต็มหรือชื่อเรียกแทนที่ตั้งไว้ การจองคาบรับชื่อบางส่วนได้เฉพาะเมื่อจับคู่ได้เพียงคนเดียว และจะแสดงชื่อที่จับคู่ให้คนตรวจ
- ข้อมูลจากโมเดลที่ไม่ผ่านสัญญาจะถูกปฏิเสธทั้งชุดก่อนเขียน
- หากฟิลด์บังคับไม่ครบ ระบบจะหยุดการส่งโดยไม่มีแฟลกให้ฝืนข้าม
- ถ้าคาบไม่มีวิดีโอ ระบบจะหยุดด้วย exit code 3 เพื่อให้คนเลือกว่าจะเพิ่มวิดีโอก่อน หรือยืนยันส่งด้วย `--without-video`
- เมื่อเผยแพร่ ระบบจะเพิ่มเนื้อหาใหม่ก่อนลบของเดิมและรักษาบล็อกที่โปรไฟล์กำหนดไว้ หากงานสะดุดกลางทางจึงกู้คืนได้โดยไม่ทำข้อมูลเดิมหาย
- คำสั่งอ่านข้อมูลใช้ฐานสำรองได้ แต่คำสั่งเขียนจะหยุดแทนการเขียนลงเพียงสำเนาเดียว
